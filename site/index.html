Self-hosted: GHCR image pulls

One docker pull increments the tag's index manifest and the platform manifest. Platform-manifest pulls of the frontend image are the cleanest "one station updated" counter (the backend image is pulled ~2.5× per station because three services use it). Releases marked mixed were built together with staging from identical content, so their pulls include staging-channel stations.

Home Assistant add-on

Two independent signals: HA analytics counts installs that opted in (a minority), while pulls of Alex's per-arch add-on images count roughly one per install per add-on version, since the supervisor prompts updates within days.

GitHub

Fresh installs git clone the repo; updates git fetch, which GitHub does not count. CI checkouts and the maintainer's machines are included, so unique cloners overstate installs. Traffic history is collected daily by github-repo-stats into this repo's traffic-data branch.

Method and caveats

Self-hosted station pulls
GitHub has no API for container download counts, so the collector scrapes each image's package "versions" page daily and resolves every digest through the registry (index / per-platform index / platform manifest / attestation). Digests sharing platform manifests are one build batch. A batch is main if its index carried the main tag in a daily snapshot, otherwise by proximity to a successful main CI run; the release label is the newest git tag at build time. Images carry no labels, so historical batches built together with staging (identical content) are mixed.
Self-hosted estimate
Per release, station pulls minus maintainer stations. Walking releases in order, pulls drain proportionally from the pool of stations on older releases; the excess is new stations. Stations whose last pull is older than days are shown as "not updating". Stations that never pull (local builds before the GHCR path, March 2026) are invisible.
Home Assistant estimate
max(HA analytics reporting installs, pulls of the most recent add-on version that has been out ≥ 7 days). Opt-in rate = reporting ÷ estimate.
Total
Self-hosted active + HA estimate; the band is ±30 % to reflect the unknowns above.
Daily series
Per-release daily pulls, HA history and the estimate history accumulate from the first snapshot (2026-08-25). Earlier points come from cumulative counts only.
